WFlash User Guide

WFlash takes firmware built by GitLab CI and flashes it into the external QSPI flash of the SAF85xx ECU through winIDEA. It only changes the file paths in your winIDEA workspace, and puts them back if anything fails.

1. Before you start

  1. winIDEA 9.21 is running with your ECU workspace (.xjrf) open, and flashing by hand with Debug → Download works.
  2. The ECU is powered and the debug probe is connected.
  3. The CAL file (*_CAL_T008_*.sre) is in the same folder as the workspace .xjrf.
  4. You have a GitLab Personal Access Token with the read_api scope (GitLab → Preferences → Access Tokens).
  5. For debugging: your App source repository is cloned on this PC. Boot Manager and Flash Bootloader repositories are optional.

2. The window at a glance

1Menu bar: debug bundle, folders, dark mode, tools, this guide. 2Flash button and progress: also shows downloads and checkouts. 3Tabs: Flash (daily work), GitLab (where the firmware comes from), Setting. 4Information: what WFlash is doing, warnings and errors.

3. First-time setup

Open the Setting tab. WFlash saves every change at once and restores it next time.

  1. Select your Profile (for example SUZ05). The GitLab URL and the projects are filled in from the profile.
  2. Paste your Access token. It is stored in Windows Credential Manager, never in a file.
  3. Choose Tools → Test GitLab connection. The Information panel should say the connection works.
  4. Under winIDEA, pick your workspace in Instance (Refresh if winIDEA was started later).
  5. Leave Reset target on. Verify samples reads parts of the flash back after programming; it adds about 3 minutes.

4. Choose the firmware

Open the GitLab tab. Each part (App, and with Advanced Debug, Boot Manager and Flash Bootloader) has the same panel.

  1. Browse to your App repository. WFlash shows its branch and commit, and warns if files have local changes.
  2. Pick the Build (configuration) you want to debug.
  3. Choose how the firmware is selected:
    • From checked-out commit: WFlash loads the CI artifact of the commit your repository is on, by itself. If that commit's pipeline is still running, it waits and loads it when the job finishes.
    • Manual: press Choose Job, pick a branch and a successful job, then download it.
  4. To debug another commit, press Checkout, type part of a branch name to filter, pick a commit and confirm. WFlash refuses while your repository has local changes; it never stashes or discards your work.
  5. To flash Boot Manager and Flash Bootloader too, turn on Advanced Debug and set their panels the same way. Their repositories are optional: without one, use Manual.
Tip. The status line under each panel tells you where the firmware came from: Cached means it was already in the download folder, Downloaded means it was just fetched from GitLab.

5. Flash the ECU

  1. Open the Flash tab and check Firmware to flash: the build, branch and commit of each part.
  2. Check the two tables. A red row has no file yet; pick one from its list. Flash stays off until every row has a file.
  3. Press Flash. WFlash connects to winIDEA, sets the file paths, checks the ECU cores and programs the flash (about 100 seconds).
  4. When the step reads Done, power-cycle the ECU and check that it runs. If you are in another window, Windows shows a notification when the flash ends.
Cancel is locked while programming. Stopping in the middle of an erase could leave the ECU empty, so WFlash lets programming finish. Cancel works before that step, and the old workspace paths are put back.

6. When something goes wrong

What you seeWhat to do
Cores not accessible … resetting againNothing: WFlash resets the ECU up to 10 times by itself. If it still fails, turn the ECU power off and on, then flash again.
Programming did not start … trying againNothing: winIDEA could not load its flash monitor, nothing was written. WFlash tries up to 3 times.
Flash failed: winIDEA could not start programming in 3 tries.Turn the ECU power off and on, then flash again.
No CAL file was found next to the workspaceCopy the *_CAL_T008_*.sre file next to the .xjrf, then Refresh in Setting.
No pipeline for <commit> or job manual / skippedPush the commit, or run the job in GitLab. WFlash waits for running jobs, not for jobs nobody started.
GitLab: token wrong or expired, missing scope, certificate errorCreate a new token with read_api; for a certificate error, ask IT to install the company certificate in Windows.
Red banner ROLLBACK FAILEDCheck the Download Files and Symbol Files in winIDEA before flashing again.
Recover by hand. If the ECU does not start after a flash, select known good files in winIDEA and use Debug → Download. Turn off Boot Manager and Flash Bootloader rows if you are not sure about them.

7. Report a problem

  1. Choose File → Export debug bundle… (Ctrl+E). It saves a zip with the log, the workspace paths before and after, and your flash history. Your token is masked.
  2. Copy the winIDEA Output view of the failed flash.
  3. Send both, with one line on what you expected.

File → Open flash history opens a CSV file (in Excel) with one line per flash: time, firmware of each part, resets, tries and result.
